## 1. 纲领：本世界为什么现在只有一个物种可活

把已归档的判决串起来，多物种失败不是三次独立失败，而是**同一个根因的三个投影**：

| 已判决 | 表面结论 | 投影回的根因 |
| --- | --- | --- |
| `feasibility.md §1` diet 轴中段死区（六种子全灭绝） | 第三营养级进不去 | 营养级轴上只有两个可活点 |
| `feasibility.md §9.5` forage_pref **证否**（方差反向塌缩 32.6%） | 资源分割不发生 | ~~果层只有草层的 0.07%，没有第二个饭碗可专精~~ **← 这条归因已被 §9.8 证否**：给了 28% 的真饭碗 + 最大选择强度，塌缩反而更深（−38.3%）。真因是**中间型最优**，不是没有饭碗 |
| `feasibility.md §7` 腐食 v2 18 配对翻正但带 −5.6% 种群代价、跨地形只 4/5 | 腐食通路太稀薄 | 尸体流量相对草层同样是零头 |
| `water_system.md` / `day_night.md` 「捕食者搬离河岸」结构不可达 | 空间分化不发生 | **水把所有个体钉在河岸，只有一种栖息地** |

**[本世界实测] 一句话根因：这个世界只有一个饭碗（河岸的草），所以只能坐得下一个食草生态型。**
金标 `plant_total=10790` vs `fruit_total=40.3`（`scripts/golden.json`）——果层是草层的 **0.37%**，
20000 步长跑下更低（§9.5 测得 0.07%）。在这种供给比下，任何「专精果实」的基因型都必然饿死，
方差塌缩是**正确**的演化响应，不是机制没点火。

**所以纲领是：先造出第二个生态位，再谈第二个物种。** 顺序不能反——先加基因、再指望生态位
自己出现，已经被 forage_pref 那次证否了（付了永久 `trait_dim` 7→8 的代价）。

### 1.1 三条候选轴（按「造饭碗」的便宜程度排序）

1. **资源轴——加厚果层。** 纯 `--set`（`fruit_max` / `fruit_regrow_rate` / `fruit_patch_threshold`），
   零代码、零种群作废；forage_pref 基因**已在 main**，代价已付。**这是第一回合。**
2. **空间轴——让第二个栖息地能活人。** 水是硬约束（`water_system.md`），但果层若够厚，
   林冠区（中海拔近水）本身就是一个和河岸草原不同的斑块。空间分化是「**局部**多物种」这个
   诉求的字面含义，需要新的读出指标（生态型 × 空间的联合分布），不是新机制。
3. **营养级轴——腐食 / 顶级捕食者。** 已知稀薄；腐食留作已翻正但带代价的价值决策，
   顶级捕食者只作快速证伪。**排在资源轴与空间轴之后**，因为它们不造饭碗，只分饭碗。

### 1.2 什么算「成功」（终局判据，先写后跑）

用户要的是「局部的多物种生态箱演化」+ 看得见的可视化。拆成四条可证伪的：

- **S1 生态位存在**：第二资源层的现存量 ≥ 草层的 10%（当前 0.37%），且不靠杀死草层达成。
- **S2 分化发生**：`forage_pref_std` 处理臂 > 对照臂，≥5/6 同向，配对 Wilcoxon p≤0.05；
  且基因分布的**形状检验**拒绝单峰（真·双峰，不只是方差变大）。
  **[修订 2026-08-02，跑之前改，理由在此]** 原文写的是 Hartigan dip test。本环境无
  `diptest` 包，而手工移植 AS 217 的 GCM/LCM 交替拟合是典型的「错了不报错、只返回一个
  看起来合理的数」——正是本项目反复警告的那类失效。改用**1-vs-2 高斯成分的参数自助
  似然比检验（BLRT，McLachlan 1987）**：EM 拟合、LR 统计量、自助零分布三部分都能对着
  已知真值的合成数据验，`tests/test_kernel.py::test_shape_test_separates_unimodal_from_bimodal`
  就在验。它对「性状替代=两个群」这个**具体**备择假设也比通用单峰性检验更有功效
  （dip 检验的是对任意单峰性的偏离）。实现在 `scripts/probe_trait_dist.py`。
  **[再修订，仍在跑之前] 形状检验的绝对 p 值在演化种群上无效，判据改为配对臂间比较。**
  实测（2000 步、seed 0、herb 携带者）：`forage_tradeoff=0.5` 给 LR=212.8 / p=0.0200（地板），
  而**中性对照 `forage_tradeoff=0.0`——基因被编译期断开、什么都做不了——同样给 p=0.0200 地板**。
  根因：演化种群不是随机样本而是**谱系**，亲缘共享基因值使分布天然呈家系团块，
  有效样本量是独立世系数而非个体数，自助零分布（按 iid 重采样）因此窄得离谱。
  故 S2 的形状部分改判为：**`blrt_lr_per_n` 处理臂 > 对照臂，6 配对种子 Wilcoxon**。
  除以 n 是因为 `2(ll2−ll1)` 随样本量线性增长而两臂携带者数不同，直接比 LR 等于在比种群大小。
- **S3 局部性成立**：两个生态型在空间上分开——生态型 × 栖息地（林冠/河岸）的联合分布
  显著偏离独立零模型（这条**必须跨地形种子**，否则是伪重复，见 `conventions.md` §6）。
- **S4 不塌方**：护栏三条同时守住——`carnivore_frac` ≥ 0.05（捕食者不灭绝）、
  `population` 相对基线在 ±30% 内、`death_thirst` 占比不恶化。

S1→S2→S3 是**串联**的：S1 不成立就不必跑 S2（这正是 §9.5 那次浪费掉的 36 个 run 的教训）。

## 2. 循环工作流（七道闸）

**一回合 = 一个可证伪假设走完七道闸。** 每回合结束在台账（§3）追加一行。
闸门是顺序的，前一道不绿不许进下一道；某道闸黄了就**降级本回合的 claim**，不是放宽闸门。

### G0 选题
从 §4 backlog **顶部**取一条。取出来必须当场能写成「假设 + 成功判据数字 + 失败判据」，
写不出具体数字说明还没想清楚——那就把它拆开，先跑一个能写出数字的探针回合。
按 `/exp` 第 1 步的字段，在目标 `docs/<topic>.md` **先建一节**（此时实验还没跑）。

### G1 净树
`git status --short` 干净、`check.py` 绿。不干净先提交——脏树上跑出的结果 provenance
对不上任何 commit（`MEMORY.md` 的 `[LEARN:tooling]` 就是这条）。

### G2 最小改动
**能用 `--set` 做到就绝不写代码。** 必须写代码时：默认关、旧路径 bit-exact、补单元测试、
`check.py --full` 全绿、提交（中文 message，说清为什么改）。
动 `in_dim` 要单独确认（作废全部演化脑）；动默认生态参数要预告 golden 重 bless。

### G3 跑
6 配对种子 × 2 臂 × 20000 步，**并发上限 6**（12 会 GPU OOM），`--json`，
产物落 `outputs/<run_id>/`，先写 `provenance.txt`（git hash + resolved config + seed 列表 + 完整命令）。
后台跑，别傻等；12 个 run 约 10–15 分钟，36 个约 27 分钟。
**空间性结论额外交叉地形因子**（`ridge_wavenumber` / `ridge_base_y`），否则是伪重复。

### G4 判决
**派 `result-analyst` 读 `outputs/`，主控不自己读日志**（十几个 run 的日志进主 context 就清不掉，
而且 fresh eyes 不知道我希望看到什么）。要求：逐种子数字 + 每个数字的出处文件 +
配对 Wilcoxon/Mann-Whitney + 效应量 + bootstrap CI + 判据逐条「达成/未达成」。
**n=6 配对的最小双侧 p 是 0.031——那是地板，不是强证据。**

### G5 落档
结果写回 G0 建的那一节，**四标签逐条标注**（`[现实]`/`[本世界实测]`/`[对应]`/`[提案，非结论]`）。
负结果照样完整写——它们是唯一能阻止同一个想法被重试的东西。
`docs/TODO.md` 加指针；§3 台账加一行；§4 backlog 按判决重排（判决要能改变下一回合选题，
否则这个回合白跑）。提交 + push。

### G6 可视化闸
**每 3 回合，或任何机制转为默认开时，必过一次。** 本项目有过教训：着色器把植物场画成
一块饱和色板，只靠读代码审了很久没发现（`CLAUDE.md`「用眼睛验证 GPU 与画布输出」）。
过法：起 `run_live.py`、headless chromium 截图（`--use-gl=angle --use-angle=swiftshader
--enable-unsafe-swiftshader`）、**人眼看**。终局交付物是「生态箱面板」（§1.2 四条判据各一张图）。

### 停机与降级规则
- backlog 空了 → 不停机，去 §4 的「补给区」按纲领生成新候选。
- 撞到需要用户拍板的岔路（会作废种群 / 会改默认生态 / 花费超过一晚）→ **不擅自选一条**，
  写进 `HANDOFF.md` 的 PENDING，然后**跳过它继续下一条 backlog**，不要停在那里等。
- 某回合判决为负 → 这是正常产出，不是失败。落档、更新 backlog、进下一回合。

## 5. R1 果层供给扫描（2026-08-02，run_id: 20260802-fruit-supply）

### 判据本身写错了观测量（本回合的真正产出）

**[本世界实测]** p4 的果层容量是 `8.0 × 20% × 16384 ≈ 26000`，现存只有 182，即容量的 **0.7%**——
果子一长出来就被吃光。而 `ecology.regrow` 是
`growth = rate × field × (1 − field/cap)` **加** `baseline = baseline_rate × cap/ref_max`：
**现存量被消费钳在 0 附近时 logistic 项跟着归零，真正在供货的只剩 baseline 那一项。**

**[对应]** 按 `underworld/ecology.py:42-49` 逐项估算每步供给流量：

### 两条必须记下来的诚实说明

**(1) [对应] `frb=0.25` 与设计意图冲突。** 相对容量的自发再生速率：草层

something」。把果层做成快速再生资源，专精它就不再是一种不同的生活方式，只是换个地方吃。
r1（frb=0.10 → 2.5%/步，仍比草快 3.7×）程度轻些但同向。**这是一笔要认的账，不是可以

**(2) [对应] 面积路线有硬天花板，到不了 20%。** `terrain.py:207` 是

于是 (i) 抬 `fruit_max` 对基线通量**完全无效**（通量 `= baseline_rate × Σ(cap/fruit_max)`，
`fruit_max` 约掉了），这正是探针一里 p3/p4 抬容量没反应的原因；(ii) 把

份额约 1.2%。**空间独特性是 `forest²` 给的，不是斑块阈值给的**——所以放宽阈值不会把果实
漏进草原，但也救不了量级。

### 我自己预注册里的算术错了（记下来，但不用它改本轮判据）

§6 立门槛时我论证「`forage_tradeoff=0.5` 下专精者在本层拿 1.5×、另一层只剩 0.5×，
所以果层至少要供到两成，专精果实才不亏本」。**这个论证是错的**：资源分割是频率依赖的。
设果层占植物总供给 `f`、专精果实者占种群 `q`，两类专精者的人均获得在平衡时相等：
`1.5f/q = 1.5(1−f)/(1−q)`，解得 **`q = f`**。

**也就是说任何 `f` 都能撑起一个比例为 `f` 的亚种群，专精者永远不亏本。** 真正卡住分化的
不是 `f` 有多大，而是**选择梯度能否压过基因流**——那取决于 `forage_tradeoff` 的**强度**
（以及有无生殖隔离），不取决于果层份额。`§9.5` 那次证否的根因诊断（「果层只有 0.07%、
无生态位可专精」）**在这个意义上也是不完整的**：0.07% 的问题不是「专精不划算」，而是
比例为 0.0007 的亚种群会被漂变和基因流直接抹平。

**但这不构成事后改判据的理由。** 判据按原文跑完、按原文判（见 §7），算术更正只用来指导
R2：R2 必须把 `forage_tradeoff` **强度**当作与果层份额同等重要的因子，而不是只开 0.5 一档。

### 7.5 渴死破在哪：代码层面已定位，且方向与真实生态相反

**[对应]** `dynamics.graze:143` 返回水 `= gain × forage_water_frac`，而草的
`gain = biomass × eat_efficiency`（无能量系数，`eat_efficiency=1.0`）→ **草每卡路里给 0.10 水**。
`dynamics.eat_fruit:174` 返回水 `= taken × forage_water_frac`，用的是**生物量**，
而 `gain = taken × fruit_energy × eat_efficiency` → **果实每卡路里只给 `0.10 / fruit_energy` 水**。

于是 `fruit_energy=4.0` 时果实每卡路里的水只有草的 **1/4**，`fe=6.0` 时只有 1/6。
把两成热量挪到果实，就等于砍掉近两成的觅食水补贴——**渴死护栏破在这里，不是玄学**。
死因分解自洽：两臂饿死都降（−0.020/−0.018），压力转移到渴死。

**[现实] 而这与真实生态相反。** 果实含水量典型 80–90%，高于草料的 60–80%；
`graze` 自己的注释就引了「Real herbivores draw much of their intake preformed」，
`biology.md` 有「预成水」一节。**当前实现让果实比草更干，是一处与文献相反的建模选择**
（草的水挂能量、果实的水挂生物量，两处口径本就不一致）。

**→ 这直接生成 R1c（§8）：给果实它应有的预成水，再看渴死护栏是否可修。**
若可修，则 R1b 的失败是口径问题而非果层路线的本质代价；若不可修，果层路线证伪成立。

## 8. R1c 果实的预成水（2026-08-03，run_id: 20260803-fruit-water）

- **假设**: R1b 的渴死护栏破裂是**水口径问题**而非果层路线的本质代价。当前果实每卡路里
  只给 `0.10 / fruit_energy` 的水（草是 0.10），把热量挪去果实等于砍水补贴。给果实

  **且** `population` ∈ 同种子基线 [0.7,1.3]× **6/6**
  **且** `death_thirst_frac` ≤ 同种子基线 +5pp **6/6**。

## 10. 三个回合合起来的真结论：水限世界里，加食物只会变成更多身体

R1 / R1b / R1c 是三次独立的失败，但指向同一堵墙，值得单独立一节，因为它改写纲领。

**[本世界实测]** 果层供能份额可以从 0.1% 一路做到 25%（这一点毫无疑问、6/6、p=0.031 地板）。
但每一次，多出来的能量都**转化成更多的身体，而不是另一种活法**：种群 +16~22%，
`mean_water` 不动，渴死随种群走（ρ=+0.90）。

这与两份已归档的判决是同一堵墙：
- `herbivore_overpopulation.md` §6：四条降密度杠杆全部失败，根因水限 + 密度尺度不变。
- `water_system.md`：**每一个有效水杠杆都让种群涨 27–72%**、捕食者占比升到 33–41%。

**合起来的命题（本纲领的核心修订）：在一个承载力由水锁死的世界里，
「增加食物供给」这条路造不出第二个生态位——它只会等比例地造出更多同一种生物。**
第二个生态位必须来自**不增加承载力**的轴：

- **(i) 重新分配现有生产力**：把总植物通量保持不变、只改变它在草/果两层之间的**构成**。
  这与 R1b/R1c 测的「加厚」是**不同的假设**，不是它的救援臂——加厚测的是「更多食物」，
  再分配测的是「同样多的食物，两种吃法」。→ **R3（§11）**
- **(ii) 分割空间或时间**：同一份资源、不同的取用地点或时段，零新增能量。
  → 原 backlog 的空间轴，`day_night.md` 的相位分箱探针可复用。

**纲领 §1.1 的排序据此更新**：资源轴不再是「加厚果层」，而是「等量再分配」；
「加厚」已证伪，不要再试。

## 9. R2 厚果层下的资源分割（2026-08-03，run_id: 20260803-partition）

### 9.1 为什么这一轮要交叉 `forage_tradeoff` 强度

§6 那条算术更正的直接后果：频率依赖下专精者亚种群比例 `q ≈ f`，**任何果层份额都撑得起
成比例的亚种群**，所以「份额不够」从来不是分化不发生的充分解释。真正卡住的是
**选择梯度 vs 基因流**——而选择梯度由 `forage_tradeoff` 的强度决定，不由 `f` 决定。
`§9.5` 那次只开了 `forage_tradeoff=0.5` 一档，**把强度当常数、只动份额**，因此它的
根因诊断（「无生态位可专精」）是不完整的。本轮把两者交叉。

### 9.2 设计：2 × 3 因子，6 配对种子

**[本世界实测] 本轮给了 28% 的真饭碗 + 最大选择强度，塌缩反而更深（−38.3%）。
所以那个归因是错的：塌缩的原因不是「没有饭碗」，是「中间型最优」。**
（复现本身很干净：−32.6% → −38.3%，两个独立配置下同向同量级。）

### 9.9 为什么中间型会最优 [提案，非结论]

**未测量适应度曲面**，以下是解释不是结论：果层的空间位置由
`terrain.py:207` 的 `fruit_capacity = fruit_max × patch × forest² × (1−rock)` 决定——
**果实长在森林里，而森林是中海拔近水带，正是所有个体本来就待的地方**。
两种资源在空间上**交织**而非分隔，于是一个个体在一生中会反复遇到两者，
**「两样都能吃」严格优于「只精一样」**。

专精只有在个体**大部分时间只遇得到一种资源**时才划算。
**→ 资源分割需要的不是「第二个饭碗」，而是「两个饭碗离得够远」。**
这恰好就是用户那句「**局部的**多物种生态箱」的字面含义，也把 backlog 指回**空间轴**：
要么把果层挪出森林带（改 `fruit_capacity` 的地形门控），要么走时间轴（昼夜错峰取食）。
**两者都会改默认世界行为，属于要用户拍板的岔路。**

**[本世界实测] 抵消剂量对草侧旋钮是非单调的**：`regrow_baseline` 0.012→0.010→0.008→0.006
给出的 fruitF 是 100.5 → 44.5 → 39.3 → 106.5。这不是噪声（幅度太大），是**生态反馈**：
砍草 → 种群变化 → 对果层的消费压力变化 → 果层现存量变化 → logistic 项跟着变。
**两层通过共同的消费者耦合，所以「按公式算出该砍多少草」不成立，只能实测扫。**

正式判决取 **t5** 为主臂，另加一个邻近臂 `G`（`grb=0.012 + plant_max=2.0`）对冲单种子噪声。

### 11.4 判决：**无法判定**（judged undecidable），因为判据的容差窄于复现噪声

18 个 run，产物 `outputs/20260803-repartition/verdict/`，
脚本 `explorations/20260803-repartition/analyze.py` + `terrain_null.py`。

| 判据 | F_grb010_pm20 | G_grb012_pm20 |
| --- | --- | --- |
| C1 中位 frugivory ≥0.20 | 达成 0.2781（6/6） | 达成 0.2981（6/6） |
| C2 总通量 ∈[0.90,1.10]× | **2/6** | **2/6** |
| C3 carn ≥0.05 | 达成 6/6（min 0.161） | 达成 6/6（min 0.074） |
| C4 pop ∈[0.7,1.3]× | 达成 6/6（0.799–1.007） | 达成 6/6（0.949–1.281） |
| C5 渴死 ≤ base+5pp | **4/6**（s4 是 +5.04pp，超线 0.04pp） | **2/6**（最差 +14.47pp） |

**字面上两臂都不通过。但这个判决不能采信**，理由在下面，而且它不是为了救结论——
**护栏宽度一个字没动，两臂也都没有被改判为通过。**

### 11.5 为什么不能采信：判据容差 ≈ 1 个复现噪声 SD

分析中派生出一个本轮最重要的量：**同种子、同配置、同代码重跑的散度**。
`A_base seed 0` 重跑 6 次（`outputs/20260803-repartition/replicate/`，主控已独立复核原始 JSON）：

| 指标 | **同种子重跑 SD** | 跨种子 SD（n=6） | 倍数 |
| --- | --- | --- | --- |
| `population` | **146.6**（CV 0.082） | 39.2（CV 0.023） | **3.7×** |
| `carnivore_frac` | **0.0527**（同一 seed 跑出 0.068–0.237） | 0.0131（CV 0.079） | **4.0×** |
| `total_flux` | 19.1（CV 0.079） | 9.6（CV 0.039） | 2.0× |
| `death_thirst_frac` | 0.0428（4.28 pp） | 0.0350 | 1.2× |

代入两条失败的判据：
- **C2 的 ±10% 窗**：比值是处理/基线，分子分母各带一份噪声 → 比值 CV ≈ √2×0.079 = **0.112**，
  即 **±10% 窗 ≈ ±0.9 个复现 SD**。一个真效应为零的配置，逐种子 6/6 落窗内的概率约
  `0.63^6 ≈ 6%`。**C2 作为 6/6 逐种子护栏，与配置好坏无关地几乎必然失败。**
- **C5 的 +5pp 线**：复现 SD 就是 **4.28pp**，即容差 ≈ **1.2 个复现 SD**。零效应下每颗种子
  约 12% 概率自己撞线。

**所以 R3 记为「无法判定」，不是「不通过」。** 这与事后放宽判据的区别是可操作的：
判据数值一个都没改，改的是**测量**——要判它必须先把噪声压下去（每格重复 k 次取均值，
噪声降 √k；或用确定性 XLA 算子）。测量修好之前，R3 的通过/不通过都没有信息量。

**§11.2 的失败判据（「无臂全过 → 资源轴整条关闭」）因此不执行**：它的隐含前提是判据可测，
而该前提被违反。资源轴**挂起**，不宣布关闭，也不宣布成功。

### 11.6 仍然可信的三件事（效应量远超复现噪声）

用**复现 SD**（不是跨种子 SD）当尺子，只有两个指标的臂间差值真的超出噪声：

1. **[本世界实测] `frugivory_frac`**：F +0.269、G +0.286，6/6 同向，p=0.031（地板），
   效应是复现噪声的 **500 倍以上**。**「同样多的食物、两种吃法」在供给端确实做到了。**
2. **[本世界实测] `forest_frac`**：F +0.066、G +0.051，6/6，p=0.031，约 5–7 个复现 SD。
   但**必须对着零模型读**：基线 0.2101 恰好坐在「按草层承载力加权」的零模型 0.2190 上；
   F 0.2756 / G 0.2610 只走完「草加权 0.219 → 果加权 0.612」全程的 **14.4% / 10.7%**。
   **种群向林冠挪了一点，远没有搬到果层所在地。**（且伪重复：同一张地图。）
3. **[本世界实测] 超调减弱但未消失**：pop 比值与渴死 pp 的 Spearman ρ 从 R1c 的 **+0.9030**
   降到 **+0.6154**（n=12, p=0.033）。F 平均 0.894（**欠**调），G 平均 1.144（仍超调）——
   两臂分列超调轴两侧。**守恒约束把种群拉回了一半，但渴死代价没跟着消失**（+4.21pp，
   甚至略高于 R1c 的 +3.56pp）。

### 11.7 一处必须更正的过度解读（分析 agent 的第 5 条结论）

分析报告写「果实吃到 27–29% 份额却没分化出果实专食者（`forage_pref_std` 纹丝不动）」。
**这条不成立**：R3 三个臂的 `overrides` 里**没有 `forage_tradeoff`**，它停在默认 **0.0**，
即 `dynamics.graze` / `eat_fruit` 里那个分支被编译期切掉，**`forage_pref` 基因对世界毫无作用**。
基因不动是必然的，不是发现。**R3 在设计上就回答不了分化问题**——那是 §9 R2 的事。
（这也再次说明为什么中性对照必须显式跑：`forage_pref_std = 0.055` 在这里就是纯漂变的读数。）

### 11.8 预标风险：方向与预测相反，但落在噪声内

预标的是「砍草会压捕食者」。实测**反向**：砍得更狠的 F 捕食者反而更高
（0.2156 vs 基线 0.1648），砍得轻的 G 反而更低（0.1394）——跟着种群**反向**走
（F 欠调→carn 高，G 超调→carn 低）。但 `carnivore_frac` 的复现 CV 是 **0.376**，
两个差值只有 0.88 / 0.44 个复现 SD，**都在噪声里，两个方向都不能声称**。
C3 护栏本身 6/6 过，无臂逼近 0.05。

### 9.10 P3 剂量项补齐（2026-08-03）：**单调，没有分化窗口**

§9.5 记的偏离已补上——加跑 `forage_tradeoff=0.5`（M 臂，6 种子 × 3 重复 = 18 run），
与 R2 的 P(0.0) / Q(1.0) 同配置同目录，三臂 `overrides` 逐字段核过**只差这一项**。
脚本 `explorations/20260803-partition/analyze_p3.py`。

| `sd`（格均值） | P(0.0) | **M(0.5)** | Q(1.0) |
| --- | --- | --- | --- |
| 值 | 0.09508 | **0.07025** | 0.05866 |
| 相对 P | — | −26.1% | −38.3% |

**[本世界实测] 单调。`M > P`（歧化方向）的种子数 = 0/6**，`bimodality_coefficient` 同样 0/6，
`blrt_lr_per_n` 1/6。**不存在「弱权衡歧化、强权衡稳定化」的分化窗口——R2 没有跨过头。**
三臂 Friedman `sd` p=0.0094。M 臂直方图也没有可复现的双峰（低值簇/谷底比 0.18，
而 Q 那个比值 2.37 的簇**再次确认 100% 来自单个 run**，是伪影）。

**[本世界实测] 挤压在半剂量已完成 68.2%**，且 **M 与 Q 在 n=6 下不可分**（`sd` p=0.4375）。

**三条必须一起写下的限制**（分析 agent 主动标的，不是我事后补的）：
1. **`M−P` 的 `p=0.03125` 不稳**：它同时是 n=6 的地板值、在**中位数**聚合口径下失守
   （p=0.09375），而且配对差紧得反常（实测差 SD 0.00627 vs 复跑噪声预测 0.02767，
   卡方下尾 p=0.0016）。**「M<P 方向 6/6」可信，「p≤0.05」不可信。**
   对照之下 `Q−P` 对口径不敏感，稳。
2. **只测了 0/0.5/1 三点。** 若分化窗口很窄（比如落在 0.1–0.3），本设计会直接跨过去。
   **「单调」这个结论只在这三点上成立。**
3. **伪重复**：果层由 forest 派生、forest 由高程派生，所以「适应度曲面单峰」只对
   **这一套河系/森林布局**成立。

**[本世界实测] 又一次印证方差那把尺子**：M 臂**格内**（同种子复跑）SD 0.0303
**大于**格均值的跨种子 SD 0.0216（比 1.40）。主导方差仍是复现噪声而非创始者，
与 `run_to_run_variance.md` 的 ICC 结构一致。分析 agent 据此给了一条有用的预算建议：
**加种子和加复跑几乎等价，但加种子还顺带减少伪重复——预算优先投种子数。**
